# Planets from Mercury to Uranus

## Goal
Show Mercury, Venus, Mars, Jupiter, Saturn and Uranus at their real apparent positions and brightness in the existing 3D sky, using authoritative game time and player location.
This is a specification only; implementation starts in a later task.

## Files to change
- `src/theroadragetrip/planets.py` (new): local ephemeris provider, six-body state, bounded cache and supported-date policy.
- `src/theroadragetrip/server/__init__.py`, `src/theroadragetrip/protocol.py`: publish observer/time-stamped planet state beside `calendar.star_sky`.
- `requirements.txt`, Windows release/build packaging and an ephemeris data directory: add only the selected provider's pinned runtime dependencies/data and offline inclusion.
- `godot/main.gd`, `godot/buildings_3d.gd`, `godot/sky_clouds.gdshader`: changed-input bindings and six shared sky contributions in Vulkan/Forward+.
- `godot/visual_test.gd`, `tools/visual_scenarios.json`, `docs/visual-testing.md`: projected-planet readiness and paired-render pixel evidence.
- `docs/planet-sky.md`, source notices/manifest, `tools/license_inventory.json`, `godot/i18n.gd`, `godot/startup.gd`: coordinate/visibility policy, source rights, reproduction and FI/EN/DE credits.
- `tests/test_planet_sky.py`, `tests/data/planet_sky_reference.json`, `godot/tests/planet_sky.gd`, `godot/tests/manifest.txt`: position, lifecycle, packaging and rendered controls.

## Behaviour / acceptance criteria
1. The supported set is exactly `mercury`, `venus`, `mars`, `jupiter`, `saturn`, `uranus`, in that stable order. Earth is the observer; Neptune is excluded. Every supported body has a finite apparent position and visual magnitude, or an explicit unavailable reason that hides that body without stale/fabricated data.
2. Use `../sky-api/app/providers/skyfield_provider.py` as the working reference: `compute_current_ephemeris()` for apparent RA/Dec, distance and magnitude, `check_body_altitudes()` for `(earth + wgs84.latlon(...)).observe(...).apparent().altaz()`, and the target map for inner planets versus outer-planet barycentres. Record the inspected sibling commit in implementation docs; do not import the sibling repository or call its HTTP API.
3. Choose the local provider before coding: compare the game's existing `ephem` support against the sibling's Skyfield/DE421 approach for magnitude availability, <=0.1-degree accuracy and offline Windows packaging. Prefer existing `ephem` if it meets these checks; otherwise use pinned Skyfield with a bundled, hashed DE421 kernel and timescale data. Document the selected provider and measured decision; loading must never trigger a network download during startup or play.
4. Compute on the Python server from `calendar.current` converted through existing Finnish UTC/DST rules and the actual car/on-foot observer coordinates, including validated elevation when available. Do not copy the sibling's `datetime.now()` or fixed city-centre/geocentric observer. State includes UTC, observer, source/version, supported flag and per-body ID, unit map direction, altitude, grid azimuth and visual magnitude. Convert true azimuth with existing EPSG:3067 convergence; Godot axes are +X east, +Y up, -Z north. Apparent directions must not be precessed a second time through the J2000 star basis.
5. Validate 2020–2040 initially, within the selected ephemeris coverage. Unsupported dates, missing/corrupt data or invalid coordinates produce explicit unavailable state and a diagnostic, while the rest of the game continues. Use an airless apparent position consistently with reference fixtures; document the simple near-horizon fade and omitted atmospheric refraction rather than mixing conventions.
6. Cache the six-body calculation by a <=10-game-second bucket and observer position quantised no coarser than 0.0001 degrees; include all provider inputs in the key and bound cache size. Time jumps, save loads, DST fold, player travel and switching car/on-foot invalidate correctly. Avoid per-tick kernel reads and per-frame astronomy; retain provider/data handles once. Follow `game-mechanics-optimizations/04_dirty_flags.md` and the shared-material principle in `41_2d_sprite_batching.md` without introducing a 2D render path.
7. Render a fixed six-entry array in the existing sky shader, outside the radiance-cubemap pass, with no planet nodes, lights, generated sky textures or per-frame allocations. At normal gameplay scale planets are unresolved points with a small antialiased footprint, stable during camera movement; brightness scales monotonically with current visual magnitude. Each body's colour must match its real naked-eye appearance in Earth's sky, using subtle, evidence-based hue differences rather than arbitrary or exaggerated tints; validate the rendered colours against authoritative visual references for all six bodies. Do not turn them into Moon-sized discs or display telescopic rings/surface detail; document the display brightness compression and footprint limits at supported resolutions.
8. Apply existing local pollution/Moon-light context as a magnitude limit, suppressing faint planets before bright ones. Uranus appears only when its current magnitude passes the dark-sky limit. Bright Venus/Jupiter can survive suitable twilight; do not reuse the stars' common night multiplier unchanged or hide every planet at sunset. Define and test a smooth daylight/twilight rule and a 0–5-degree horizon fade; no below-horizon contribution. Clouds, full overcast, terrain/buildings and the opaque Sun/Moon discs occlude planets; no planet light is added to the world.
9. Preserve Sun/Moon phases, lunar surface orientation and catalogue-star coordinates/visibility. Planet positions remain celestial through camera rotation, zoom, time acceleration and travel; same-brightness point footprints stay bounded across screen resolutions and projection FOVs. Missing planet fields from an older server hide the layer cleanly.
10. Add real-map named scenarios selected using computed ephemerides: dark rural outer planets including Uranus, Mercury/Venus twilight, urban faint suppression, below-horizon/day/full-overcast controls, and a same-place time-shift/camera-rotation check. Cover all six across scenarios rather than requiring impossible simultaneous visibility. Freeze valid past game dates, use the actual 3D sky camera, and capture only after ordinary map readiness plus matching UTC/observer/source and unobscured predicted planet pixels.
11. Readiness must measure each planet's actual contribution using paired planet-on/off renders at predicted screen positions; record body IDs, directions, magnitudes, projected pixels, contrast and hidden-control results. Uniforms/counts alone cannot pass. Restore normal rendering before final captures. Run native Windows Godot explicitly with `--rendering-method forward_plus --rendering-driver vulkan`, record the active renderer and GPU, and inspect every accepted screenshot with an enlarged crop where necessary.
12. Profile matched native Windows before/after rural and city views: server ephemeris/cache cost, frame p50/p95/p99/worst, GPU time, draw calls, memory and update frequency. Expect no new draw calls or lights; investigate >10% p95 regression or astronomy-caused server tick overruns above 33 ms. Session restarts and time jumps must not grow resource counts or leave stale bodies.
13. Before shipping any new dependency or dataset, retain exact source/version/URL/hash, redistribution licence text and required attribution for the chosen provider, kernel and timescale data, plus any reused sibling code's applicable licence. Record them in docs/inventory and displayed FI/EN/DE credits; unresolved redistribution rights block bundling. Include offline Windows release smoke verification, not only the development checkout.

## Tests to add
- `tests/test_planet_sky.py::test_positions_against_independent_reference`: all six against pinned independent JPL Horizons or equivalent fixtures across dates/locations, DST/fold and horizon crossings; <=0.1-degree angular error above 10 degrees, magnitude tolerance documented per model; catches mirrored axes, city-centre/clock mistakes and frame double conversion.
- `tests/test_planet_sky.py::test_cache_time_travel_and_unavailable_state`: calls/cache bounds, observer changes, save/time jumps, unsupported years and invalid data; catches stale bodies, unbounded work and fabricated fallback coordinates.
- `tests/test_planet_sky.py::test_offline_assets_and_scenario_contract`: pinned rights/hashes, packaged kernel/timescale resolution with networking blocked, exact six IDs and real scenario coverage; catches runtime downloads, missing release data and empty-sky false passes.
- `godot/tests/planet_sky.gd::test_projection_photometry_occlusion`: actual shader pixels for east/west directions, magnitude ordering, realistic body-specific colour, twilight/pollution/Uranus limits, clouds/horizon/Sun/Moon masking and camera/FOV stability; catches incorrect placement, color drift, white clipping, giant discs and hidden-control leakage.
- `godot/tests/planet_sky.gd::test_shared_resource_lifecycle`: older/missing state, repeat updates, scene reloads and bounded uniforms/resources; catches stale points, per-body nodes/lights and resource growth.
- Named native scenarios in criterion 10 plus existing star and Moon controls: fail if correct-renderer readiness, visible planet pixels, expected hidden bodies or inspected screenshots are absent.

## Out of scope
Neptune/Pluto, labels and constellation lines, telescope mode, rings/moons/surface textures, eclipses/transits/planet occultation prediction, sky-api service changes, replacing the existing solar/lunar ephemerides, and removing legacy 2D/2.5D code.
