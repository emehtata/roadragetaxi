# RTX developer trial — 1 November 2026

The experimental launch works on native Windows with NVIDIA path tracing and
DLSS Ray Reconstruction. It remains an opt-in developer trial. Scene preparation
is complete, but the trial does not certify every scene, temporal artifact or
hardware configuration. Use [the adoption guide](nvidia-rtx-godot.md) for build
and launch instructions and [readiness Step 7](rtx-scene-readiness.md#step-7-prove-readiness-and-enable-a-controlled-rtx-trial)
for the remaining acceptance work.

## Build and machine

- NVIDIA `nvidia-pt-dlss-dev`, source `382d9d6bf0274af34b85d3cbcd98981de41cbd62`,
  Godot 4.8-dev, with [the FLOAT4 CUSTOM0 patch](../tools/rtx/custom0.patch).
- Native Windows x86-64 executable, cross-compiled under WSL with LLVM-MinGW
  20261020 / Clang 23.1.4. WSL does not render the game.
- NVIDIA GeForce RTX 5060, 8 GB; Windows driver 617.42, Vulkan 1.4.351.
- Streamline SDK 2.10.0 release runtime DLLs beside the executable. The fork
  allows downloaded plugins; logs show signed plugins loaded from NVIDIA's
  NGX cache, including cache version `134672`. Installed DLL hashes alone do
  not pin those downloaded components.
- One sample per pixel, two bounces, DLSS Ray Reconstruction, native scale
  1.0 or Quality scale 0.66; Frame Generation off. Asynchronous path-tracing
  shader compilation is disabled to avoid recording placeholder materials.
- Isolated game worktree with application name `Road Rage Trip RTX Trial`,
  separate Godot imports and user settings. The live game checkout's project
  name and default Compatibility renderer are unchanged.

## Material compatibility and rendered evidence

The July `nvidia-pt-dlss` revision failed the initial street trial with missing
UV2/CUSTOM0 input and unsupported discard in ray hit shaders. The November
development branch fixes UV2 and discard translation. Two remaining issues
required changes:

1. `CUSTOM0` was declared but always zero. Our building shader receives window
   layout through FLOAT4 CUSTOM0. The engine patch records its attribute
   offset, fetches/interpolates that data in hit shaders, and preserves zero
   for absent/unsupported formats. CUSTOM1–3 and other formats are outside
   this game's patch. CPU and GPU geometry layouts both become 160 bytes.
   The client requires the patch's `rrt_rtx_custom0` feature marker.
2. The road shader used `dFdx`/`dFdy`, unavailable in ray hit shaders. Its
   pattern footprint now comes from camera zoom and internal resolution,
   including DLSS scaling, and updates existing/new chunk materials.

The initial asynchronous compilation probe omitted custom-material cars and
buildings despite waiting ten seconds and ninety frames. Synchronous
compilation renders them, at the cost of cold-start and new-material stalls.
The fork also prints `OpTypeForwardPointer is not supported yet`; no shader
compile failure accompanied the successful patched captures. Keep that upstream
diagnostic visible when investigating future material failures.

| Capture | Inspected result |
| --- | --- |
| Forward+ material baseline | Actual game taxi, building/windows and wet road material in a small controlled scene. |
| Unpatched development path tracer | Taxi returns with synchronous compilation, but building windows are absent. |
| Patched path tracer | Building windows return; paint, glass, taxi sign, lamps and contact lighting render. |
| Outdoor raster baseline | Native Windows Forward+/Vulkan daytime Oulu; road, buildings, cars and HUD align. |
| Dry daylight, RTX native | Buildings retain procedural windows; road markings, vehicles, pedestrians and HUD align at 1280×720. |
| Wet night, RTX Quality | Lit windows, streetlights, cars and road remain present after an eight-second drive and a live resize to 1440×900. Snow/slush particles and HUD remain 2D overlays. |
| RTX home view | Three enter/leave cycles followed by re-entry and resize succeed. Walls/floor render, but the black ceiling area and interior lighting need an art/geometry review; this is not accepted interior quality. |

The material probe is reproducible from the repository root in PowerShell
(create the output directory first):

```powershell
& 'C:\Godot\rtx\godot.windows.editor.x86_64.llvm.console.exe' --path .\godot `
  --rendering-method forward_plus --rendering-driver vulkan `
  --script res://tools/rtx_material_probe.gd -- --rtx --output=C:\Temp\material.png
```

Omit `--rtx` for raster. The probe waits at least ten seconds and ninety frames.
Use the same compiled engine for both sides when isolating renderer behavior;
the initial baseline above used stock 4.7.2, so it also includes an
engine-version difference.

## Performance sample

One 20-second `--bench` session per mode, discarding the first five seconds,
on Oulu at 1280×720. Camera/start location, sun altitude 35°, azimuth 135°,
cloud cover 0 and road wetness 0 were fixed. Each mode used a fresh simulation
with the same requested start time; moving populations/weather overlays are
not an identical replay. Default VSync/presentation remained enabled and capped
most results near 60 FPS. These are a frame-pacing smoke sample, not uncapped
throughput or a statistically established DLSS speedup.

| Mode | Mean FPS | Median / p95 / p99 frame ms | Mean 3D GPU ms | Peak device VRAM MiB | Exit |
| --- | ---: | --- | ---: | ---: | --- |
| Stock 4.7.2 Compatibility | 60.0 | 16.67 / 16.80 / 26.45 | 0.20 | 1,845 | 0 |
| Patched fork Forward+ outdoor raster | 59.8 | 16.66 / 17.17 / 27.12 | 0.94 | 3,023 | 5: shutdown crash |
| RTX native | 54.6 | 16.66 / 17.11 / 135.64 | 6.66 | 3,208 | 0 |
| RTX Quality | 60.0 | 16.67 / 17.00 / 26.30 | 3.97 | 3,392 | 5: shutdown crash |

GPU timing is the game's `render_3d_gpu` section. VRAM is a one-second
`nvidia-smi` sample of the entire device, including desktop/other applications
and startup; it is not the game's isolated allocation. GPU sampling and server
runs were sequential, with no engine build running during measurements.

Native RTX had eleven frames above 66 ms and a worst frame of 196 ms, despite
the five-second exclusion. Quality had a 51 ms worst frame. Inspect synchronous
material compilation, geometry capture and streamed updates before attributing
these pauses to GPU shading; this run does not isolate their cause. A lower
Quality GPU time does not itself prove lower end-to-end input latency.

**Shutdown is an unresolved stability gate.** Forward+ raster and Quality both
printed complete BENCH JSON and then crashed with signal 11/exit 5. The daylight and
night street runs also captured their images before the same shutdown crash.
Native benchmark, small material probes, capability test and home lifecycle
runs exited cleanly. A saved image alone is therefore not evidence of clean
shutdown.
The failure therefore affects the fork's raster path too; the current evidence
does not identify whether Streamline, engine cleanup, the toolchain or the local
patch is responsible. Do not hide the nonzero exit or count these as clean
passes. Reproduce with symbols and a minimal scene before distributing a build.

## Validation and limits

`make godot-test` passes on upstream 4.7.2 (main suite: 3,873 checks, zero
failures; interior suites: 35 plans, zero failures). The four relevant Python
render-style/platform tests pass, as does the offline server/client sample
selftest. The native GPU capability/configuration test also passes with exit 0.
The development fork imports the isolated
project without script/resource errors. Headless validation covers shared
API compatibility, not GPU output.

Stock Godot rejects `--rtx` with a specific missing-NVIDIA-API explanation and
exit code 2. The fork without Streamline runtime rejects missing DLSS support;
an unpatched development build is rejected for the missing material patch.
The recorded `RTX_TRIAL` JSON reports the actual GPU, driver, renderer,
executable, source identity, feature checks and configured viewport.

The drive/resize and repeated interior lifecycle checks are smoke tests.
Screenshots do not establish ghosting-free motion or correct off-screen
reflections. Before expanding the feature, inspect video while moving pooled
vehicles/pedestrians, zooming and streaming many chunks; test bridges, foliage,
water/alpha edges and dense lighting; compare additional GPUs and drivers.
Set frame-time/VRAM budgets before acceptance. Shipping also requires matching
export templates, a clean-machine package test and runtime license inventory.
